# MVP 범위와 플레이테스트

## 1. MVP 목표

첫 프로토타입은 콘텐츠 양이 아니라 다음 가설을 검증한다.

> 바둑의 착수 판단과 돌 덱의 순환이 서로를 강화하는가?

## 2. 확정 범위

| 항목 | MVP 범위 |
|---|---|
| 바둑판 | 1막 7×7, 2막 9×9 |
| 시작 덱 | 10장 |
| 기본 패 | 4장 |
| 플레이어 색 | 항상 흑 |
| 패 규칙 | 단순패 |
| 특수 돌 | 일반석 포함 6종 |
| 유물 | 8종 |
| 부적 | 5종, 최대 2개 보유 |
| 일반 적 | 3종 |
| 지도 구성 | 막마다 지도 노드 5개 후 보스전 |
| 대국 수 | 선택한 지도 노드에 따라 변동, 막당 일반 전투 1~3회 |
| AI 구성 | 1막 기본 덱+전용 착수로 재개하는 판면 유지형 2단계 부활, 2막 고유 특성·전용 카드 |
| 최종 대국 | 9×9 MVP 보스 1종 |
| 맵 노드 | 대국, 상점, 사건, 도장, 보스 |
| 목표 런 시간 | 20~30분 |
| 그래픽 | 기능 확인용 2D UI |

## 3. MVP에서 제외

- 11×11 이상의 판
- 대규모 영구 해금 콘텐츠. 단, 돌 카드·부적·유물 해금 구조는 설계에 포함
- 온라인 대전
- 사활 자동 판정
- 복잡한 연출과 서사 분기
- 20종 전체 특수 돌
- 40종 이상의 유물
- 실시간 초읽기

## 4. 필수 프로토타입 기능

### 바둑 엔진

- 합법 수 판정
- 그룹 및 활로 계산
- 포획
- 자충수 금지
- 단순패
- 패스와 대국 종료
- 면적 계가 및 덤

### 덱 엔진

- 섞기, 드로우, 버림, 재순환
- 패 한도
- 카드 확인과 순서 변경
- 임시 패 한도 증가
- 판 위 돌의 병종 상태 저장

### 효과 엔진

- 조건, 시점, 대상과 횟수 제한
- 동시 포획 효과 큐
- 유물과 돌 효과 로그
- 착수 미리보기

## 5. 플레이테스트 핵심 질문

### 재미

- 패의 병종이 착수 선택을 흥미롭게 바꾸는가?
- 특수 돌 효과를 위해 나쁜 수를 두는 유혹이 재미있는가?
- 빌드가 실제 기풍의 차이로 느껴지는가?

### 불편

- 원하는 일반 착수를 손패가 방해한다고 느끼는가?
- 매 착수 전 읽어야 할 정보가 너무 많은가?
- 드로우 애니메이션과 효과 처리 때문에 흐름이 끊기는가?

### 학습

- 초심자가 활로와 포획을 자연스럽게 이해하는가?
- 결과 화면만으로 패배 이유를 설명할 수 있는가?
- 특수 돌이 바둑 개념을 가르치는가, 가리는가?

## 6. 수집 지표

| 지표 | 목적 |
|---|---|
| 한 대국 평균 착수 수 | 판 크기와 덱 순환 횟수 확인 |
| 턴당 평균 고민 시간 | 인지 부하 확인 |
| 병종별 선택률 | 손에 있어도 사용하지 않는 돌 파악 |
| 병종별 효과 발동률 | 조건이 너무 쉽거나 어려운지 확인 |
| 일반석 선택률 | 일반석의 안정성 가치 확인 |
| 패스 시점과 횟수 | 종료 규칙과 점수 이해 확인 |
| 포획 수와 최종 승률 | 포획 편향 확인 |
| 덱 크기와 승률 | 덱 압축 우위 확인 |
| 흑 고정 플레이어 승률 | 판 크기별 덤과 AI 난이도 조정 |
| 종료 후 남은 죽은 돌 후보 | 직접 포획 규칙의 불편 측정 |

## 7. 중단 기준

다음 문제가 반복되면 콘텐츠 확장보다 코어 규칙을 먼저 수정한다.

- 플레이어가 대부분의 턴에 병종을 보지 않고 위치만 선택함
- 반대로 바둑 수보다 카드 효과만 보고 착수함
- 시작 패에 따른 승률 차이가 지나치게 큼
- 죽은 돌 직접 포획 때문에 종반이 반복적으로 늘어짐
- 덱 압축이 모든 다른 보상보다 우선됨
- 일반석이 항상 제거 대상이거나 항상 최적 카드가 됨

## 8. 테스트 순서

1. 특수 돌 없이 7×7 기본 바둑, 단순패와 자동 계가 검증
2. 10장 덱과 4장 패의 순환 검증
3. 일반석·척후석·수호석·희생석 추가
4. 1막 AI의 판면 유지형 2단계 부활과 전용 착수 재개 검증
5. 다섯 지도 노드와 일반 전투 1~3회 경로 제한·상점 연결
6. 9×9 판 확장과 2막 전용 카드 추가
7. 9×9 MVP 최종 대국 검증
