## 4. 모순 — 반드시 인간 결정 게이트로 남는 항목

### CONFLICT-01 (BLOCKING-LATER) — 정확한 층 데이터 vs 밸런스 자동 조정

- **원문 A** (`00-user-request.md` §정확한 층 데이터): 바위 좌표, W호위 좌표, W주머니 20/24/30을 **"정확한 층 데이터"** 로 지정한다.
- **원문 B** (`00-user-request.md` §필수 테스트·밸런스): 밸런스 목표를 벗어나면 **"호위 수·적 주머니·바위 배치만 조정하라"** 고 지시한다.
- **충돌:** B를 실행하면 A가 지정한 정확값이 깨진다. 두 지시는 동일 문서 안에서 상호 배타적이다.
- **적용 결정(HDD-006):** **A 우선.** 층 표의 값은 인간 확정값으로 **동결**한다. 하니스가 목표 승률을 벗어나도 **자동으로 값을 바꾸지 않는다.** 측정 결과와 충돌을 보고하고 **후속 인간 decision gate**로 남긴다.
- **구현·검증에 대한 구속력:**
  1. Hermes/Codex는 밸런스 결과를 이유로 `FLOOR_W_POUCH`, `GUARDS_W`, `ROCKS` 값을 변경해서는 안 된다.
  2. 밸런스 하니스는 **측정 성공 시 exit 0**이며, 목표 이탈 여부는 리포트의 `in_range: true|false` 필드로만 표기한다. 목표 이탈을 테스트 실패로 취급해 값을 튜닝하도록 유도하지 않는다.
  3. 이탈이 관측되면 `07-codex-result.md`/`11-final-summary.md`에 **"밸런스 목표 미달성 — 인간 결정 필요"** 를 숨기지 않고 명시한다. 이 상태는 **성공으로 포장하지 않는다**(AGENTS §11-10).
  4. 이 항목 때문에 R-D7의 "밸런스 목표"는 **자동 통과 기준이 아니라 측정·보고 의무**로 해석한다.

## 8. 요약

1. 저장소에 게임 소스는 **전혀 없다.** 전부 신규 구현이며 Hermes/Codex가 유일한 구현자다(HDD-001).
2. `node_modules`가 이미 오프라인 제공되어 있으므로 `package.json`은 **실측 버전에 정확히 핀**해야 하고, 미설치 도구(ESLint·Testing Library·Playwright)를 **가정하지 않는다.**
3. 원문의 모든 수치·좌표·한국어 문자열·AI 점수항은 **동결 계약**이며 구현은 이를 1:1로 재현한다.
4. **CONFLICT-01**(정확한 층 데이터 vs 밸런스 자동 조정)은 HDD-006에 따라 **정확값 우선**으로 처리하고, 밸런스 이탈은 **자동 튜닝 금지 + 인간 게이트**로 남긴다.
5. OPEN-02(폰트)와 OPEN-03(실브라우저 측정)은 외부 의존성·네트워크가 걸린 항목이므로 **인간 승인 전 진행 금지 범위**를 명확히 두고 계획했다.
