# Human Design Decisions

| ID | 상태 | 영역 | 결정/질문 | 결정 주체 | 구현 영향 |
|---|---|---|---|---|---|
| HDD-001 | 확정 | 역할 | Claude Code는 읽기 전용 요구 분석·구현 계획·수락 기준 및 fresh 독립 검증만 담당하고, Hermes/Codex가 유일한 제품 코드 구현자·결함 수정자다. | Human | AGENTS.md의 기존 역할 분담을 그대로 적용한다. 중단된 잘못된 Claude 구현 dispatch의 생성 파일은 제거·원상복구했다. |
| HDD-002 | 확정 | 기술 | Vite + React 18 + TypeScript, 런타임 의존성 React/ReactDOM만, 순수 `src/engine.ts`, Vitest, 380px 모바일/430px 데스크톱을 사용한다. | Human | 계획·구현·검증의 고정 계약이다. |
| HDD-003 | 확정 | 게임 규칙 | 7×7 바둑, positional superko, 주머니 경제, 왕돌, 3개 층, 유물 6종, AI 휴리스틱과 모든 수치는 사용자 원문 그대로 구현한다. | Human | 명세와 다른 창작·수치 변경 금지. |
| HDD-004 | 확정 | UX/비주얼 | 한국어 전용 화면 흐름, SVG 바둑판, 인장 모티프, 지정 색상·모션·모달·상태 문구를 사용한다. | Human | 사용자 원문의 문자열과 토큰을 수락 기준에 포함한다. |
| HDD-005 | 확정 | 검증 | 필수 단위 테스트, 층별 무작위 시뮬레이션 3회 이상/400수, 색 반전 AI 층별 12회 밸런스 하니스를 실행한다. | Human | 실제 명령 출력과 결과를 logs에 보존한다. |
| HDD-006 | 확정 | 밸런스 충돌 처리 | 층 표의 바위·호위·적 주머니 값은 정확한 인간 확정값으로 동결한다. 하니스가 목표 승률을 벗어나더라도 자동으로 값을 바꾸지 않고 측정 결과와 충돌을 보고해 후속 인간 decision gate로 남긴다. | Human/Hermes 해석 | 같은 문서의 “정확히 이 값”과 “벗어나면 값 조정” 충돌에서 더 엄격한 정확값 우선 원칙을 적용한다. |
| HDD-007 | 확정 | 버전 관리 | 사용자의 별도 요청 전 commit/push/reset/rebase/history rewrite를 하지 않는다. | Human | 워킹트리 변경과 증적만 생성한다. |

현재 구현을 막는 미결정 게임 디자인 항목은 없다. 밸런스 목표와 동결 수치가 실제 측정에서 충돌할 경우에만 후속 인간 결정이 필요하다.
